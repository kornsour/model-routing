## Calibration: `exp05_calibrate_haiku`, the 8 "hard" tasks on Haiku, $0.96

**Haiku passed 8/8**, using 12–23 turns and $0.07–$0.17 per task.

## What this means

1. **The task set has no headroom for routing yet.** The cheapest model
   passes every hard task, so "always Haiku" is optimal, and any router can
   only add overhead. Before the confirmatory run, the set needs tasks that
   Haiku fails 30–50% of the time. Human difficulty labels did not track
   model capability.
2. **Routing overhead is the dominant cost of C1.** A forked Opus router
   call cost about $0.08 per task, because it re-reads the parent context.
   That is often more than the Haiku worker it chose ($0.03–$0.13). C1 only
   wins when the parent model is much more expensive than the worker *and*
   the task is large enough that the worker saving beats a fixed router
   cost.
3. **The scope rule penalized thorough models.** Opus and Sonnet fixed
   `inv-race-01` correctly, then updated a docstring the fix had made stale,
   in a file outside `allowed_paths`. They failed on scope. Every brief now
   states its scope (#9); this pilot's B and static-Sonnet pass rates are
   pessimistic by one task.
4. **The Claude CLI reports cumulative cost for resumed and forked
   sessions** (router $0.169 = setup $0.086 + its own $0.083). List-price
   accounting was unaffected; the runner now records each session's share
   (#9).
5. **Sample size.** The pass/fail results of C1 and B differed on 33% of
   tasks. Resolving a 5-pt margin at that rate needs about 1,000 paired
   task-trials; a 10-pt margin needs about 260.
6. **Estimates ran low for Opus.** Opus worker sessions cost $0.18–$0.48
   (about 1.9× the estimator's assumed profile). The whole pilot still
   landed at $4.84 against a $2.01–$9.92 estimate.
