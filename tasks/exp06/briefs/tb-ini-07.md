`src/toolbelt/iniconf.py` is our own INI reader, used by both the deploy tooling and the job runner so they read `services.ini` identically. The platform team has been writing `services.ini` files to a format spec that the module only partly implements, and the gaps now cause outages: a `#` inside a quoted MOTD truncated it, a self-referencing value crashed the runner with a `RecursionError` instead of a config error, `$$` isn't understood, `[worker : api]` inheritance is ignored, and mixed-case keys (`Log_Level`) fail lookups. Please make the module implement the format below. Keep `parse`, `Config`, `ConfigError`, `sections`, `get`, `getint` and `getbool` (they are used elsewhere; the visible test shows the basic usage).

**Syntax.** Lines are processed in order. Blank lines and lines whose first non-space character is `#` or `;` are ignored. `[name]` starts a section; `[child : parent]` (spaces around `:` optional) starts a section that inherits from `parent`. Section names are case-sensitive and surrounding whitespace inside the brackets is ignored; a malformed header (e.g. `[a`) is an error. Other lines are `key = value` or `key: value`; keys are case-insensitive (store and look them up lowercased); whitespace around keys and values is stripped. An unquoted value ends at an inline comment, which is a `#` or `;` *preceded by whitespace* (so `a#b;c` is kept whole). A value that starts with `"` is quoted: it runs to the closing `"`, may contain `#` and `;`, supports the escapes `\"`, `\\`, `\n` and `\t` (any other escape is an error), and may be followed only by whitespace or an inline comment. An indented non-blank line that follows a key line and is indented more than it is a continuation: its stripped text (comment removed) is appended to the value with a newline (so `hosts =` followed by three indented lines gives `"\none\ntwo\nthree"`). A blank line ends a continuation. Quoted values cannot be continued.

**Errors while parsing** raise `ConfigError` (a `ValueError`) with a `lineno` attribute (1-based) where a line is to blame: a key before any section, a duplicate key within a section (case-insensitively), a duplicate section, a line that is neither a header nor `key = value`, and bad quoting. After parsing, inheritance from a section that doesn't exist, inheritance cycles (including a section inheriting from itself) and `DEFAULT` inheriting from anything are also `ConfigError`.

**Lookup.** A key is looked up in the section, then along its inheritance chain, then in `[DEFAULT]`. `sections()` lists sections in file order without `DEFAULT`; `has_section()` is False for `DEFAULT`; `keys(section)` lists every key visible from the section without duplicates: the section's own keys in file order, then each ancestor's in turn, then `DEFAULT`'s.

**Interpolation** happens when a value is read (every getter, quoted values included). `${key}` refers to `key` as seen from the section *being read* (not the section where the value was written), so a `url = https://${host}:${port}/` defined in `[base]` gives each child its own host and port. `${section:key}` reads from that section (and interpolation inside it is then relative to that section). `$$` is a literal `$`. A `$` followed by anything else, an unterminated or empty `${}`, a reference to a missing key or section, and a reference cycle are all `ConfigError`; the cycle error's message contains the word "cycle". Long acyclic chains of references (hundreds deep) must work.

**Getters.** `get(section, key, default=<missing>)` returns the interpolated string; if `default` is given and the section or key doesn't exist, return `default` unchanged, otherwise a missing section or key is a `ConfigError`. `getint`, `getfloat`, `getbool` and `getlist` take the same `default` (returned as-is when used). `getbool` accepts `1/yes/true/on` and `0/no/false/off` case-insensitively and raises `ValueError` otherwise. `getlist` splits on newlines if the value contains one, otherwise on commas, strips items and drops empty ones.

Add tests; keep `python -m pytest -q` green; only change `src/toolbelt/iniconf.py` and the tests.
