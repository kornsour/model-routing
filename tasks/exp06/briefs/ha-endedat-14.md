Problem: `lineage.Run.EndedAt` (in `internal/lineage/run.go`) is `time.Time` tagged `json:"ended_at,omitempty"`. `omitempty` never applies to structs, so every run that hasn't ended serializes as `"ended_at":"0001-01-01T00:00:00Z"` — a nonsense timestamp a client will parse and render as real. It also survives a terminal PATCH transition: `PATCH {"status":"succeeded"}` with no `ended_at` leaves the run succeeded with an end date in year 1.

Fix: change `EndedAt` from `time.Time` to `*time.Time` throughout, so "not ended" serializes as JSON `null` (absent is not representable for a top-level field without an extra omitempty-on-pointer, which *does* work correctly — `*time.Time` with `omitempty` omits the field entirely when nil, which is the correct behavior here). Additionally, have the server set `ended_at` to receive-time on a terminal PATCH transition (`succeeded`/`failed`/`cancelled`) when the client didn't supply one — mirroring the courtesy `started_at` already gets on POST (see `internal/api/api.go`'s `record` handler, which does `if run.StartedAt.IsZero() { run.StartedAt = time.Now().UTC() }`).
